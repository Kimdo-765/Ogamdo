      Local runtime (Ollama)
      
          
      
            A role target, not a job backend. It cannot run Main — there is
            no session, no tool loop and no resume behind it, and main
            is not routable in any case. It is offered only for roles that have an
            adapter: today monitor, whose input is six log lines and whose
            output is one sentence, so a wrong answer costs nothing and a free one
            is worth having.
          
      
          
          
          
          
      
            
            
            
          
      
          
            VRAM is the real constraint: one 12 GB card holds one ~7.5 GB model.
            Pinning two roles to two different local tags makes them evict each
            other, and the first call after an eviction pays the load again.

            SEPARATE decision from running the judge, and it was one switch until
            2026-09-03. Job cc38cfa29161 is the gate ON: prejudge scored
            flag_likelihood=0.00, blocked the ship, and the sandbox never ran — the job

            runs and still logs every issue it raised, and a bypassed block is recorded as
            prejudge WOULD have blocked ship — a near miss you can see.
            Default ON, so an upgrade changes nothing for a deployment that relies
            on it.
                
        
      
        
      
          
          
            A model re-reads every running job's appended output and writes anything it
            judges to be a real flag into <job>/flag_grain.txt. Pick its
            model in Model presets → harvester.
            
      
            It exists because FLAG_RE carries a fixed alphabet of ~20 known
            prefixes. Job 29f1d8f14268 captured REVERSSEUM{…} and
            fed8eedff33d captured pokactf2024{…} — neither prefix is on
            that list, and both were recovered only because the solver happened to print
            the FLAG_CANDIDATE: marker. The harvester accepts any braced
            string and asks a model whether it is real.
            
      
            Advisory only. It appends to one text file; it cannot write
            meta.flags, set a status, or end a job. That restriction is the
            safety argument: run.log was removed as a flag source in
            2026-07 after three jobs false-finished on fakes scraped from a web-search
            summary and from exploit.py's own print() source.
            A component that can only append to a file cannot repeat that.

            It has its own role above, so you can point it at a cheap model
            independently of the stack a job runs on — this is a judgement
            about the work, not part of doing it.

            only when a job's log has actually grown.

            This switch is now the only gate. It used to share the decision with

            you selected; the Timeline still renders beside it, because "what

            default ON to preserve historical behaviour: a feature being retired should
            not come back because a settings read failed. The
            MONITOR_ENABLED=0 env kill switch still wins independently.
                
        
      
        
      
          
          
            OFF, the default: the cap above is the only authority and nothing touches a
            slot's cgroup while a job runs. ON lets a job raise its own slot for the run
            and hand it back afterwards. Usage sampling runs either way.
            
      
            rev and crypto start at base × 2; every other
            module starts at the base. A real cgroup OOM raises the slot 1.5×, at most
            twice, and never past base × 4.
            
      
            The expansion is a MULTIPLE of your per-slot setting, so lowering that
            lowers the expansion with it — at a 2g base, rev gets 4 GiB and the OOM
            ceiling is 8 GiB. web was removed from the expansion list on
            2026-08-25 and now starts at the base.
            
      
            The safety budget is 70% of the VM, and it counts SLOT caps only — the
            runner and the challenge containers a job spawns are siblings charged to
            the VM, not to the slot, so this gate will not warn you about them.
                
        
      
        
        
      

        
      
        
        

        
      Venue VPN — reach CTF servers that only exist on the contest LAN
      
        
      
          
          
            The laptop at the venue dials in as a WireGuard peer and this box routes the
            venue's subnets to it. The tunnel terminates in the WSL VM, not
            Windows: with networkingMode=bridged the VM is its own LAN host with
            its own default route, so a Windows WireGuard profile carries Windows' traffic and
            none of Ogamdo's. Every worker, runner and challenge container inherits the route
            through the docker bridge — nothing per-container to configure.
          
        
      
        
        
        
        
        
      
          
          
          
          
        
      
        
      

        
      
        

        
        
      

        
      
          
          
        
      
      
      

      
      
        
      Provider model presets
      
        
      
          Claude, Grok, and GPT each keep their own named presets and active
          selection. Switching the job provider therefore switches to that
          provider's active preset automatically. Presets pin per-agent models +
          reasoning effort. Configurable: main (the CTF agent) and
          its effort, plus judge (prejudge / postjudge
          + judge subagent), reviewer (the /retry hint
          reviewer, separately overridable), recon, debugger,
          triage, report, and monitor
          (Claude/Grok only; GPT uses its token-free Timeline). A blank slot =
          inherit: main + effort fall back to the
          per-job picker / global Settings values above; judge / report follow main;
          reviewer follows the judge slot (then main); recon / debugger /
          triage follow main (cache-aligned); Claude/Grok monitor keeps its cheap default. An
          explicit per-job model or effort still wins over the preset.
          ⚠ recon / debugger / triage normally
          share the main model for cache-prefix alignment — pinning them to a
          different model works but sacrifices that cache locality (higher cost /
          latency). Stored in /data/model_presets.json; applies to the
          next job.
        
      
        
      
          
          
          
          
        
      
        
      
        
      
          
          
      
            
            
            
          
      
        
      
        
      
        
      
          
          
        
      
      
      

      
      
        
      Cloudflared tunnel — OOB collector
      
        
      
          Opens a public *.trycloudflare.com quick-tunnel to the api and
          auto-fills the Callback URL in this same section, so remote bots (XSS / SSRF /
          blind RCE) can beacon back to the built-in collector. Runs as a sibling
          container, so it survives api redeploys and keeps a stable URL. A dead tunnel
          stays dead — re-roll manually (Cloudflare rate-limits fresh tunnels).
        
      
        
      
          ⚠ No auth token set. This tunnel exposes the ENTIRE api to the
          public internet — including /api/terminal (an interactive shell / RCE)
          and settings-write. Anyone who learns the URL gets shell on this host. Set an
          Auth token above to lock everything except the public collector.
